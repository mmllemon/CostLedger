# MagicPath 提示词 · CostLedger 施工单位成本岗 UI（现行基线）

> **现行基线（2026-10-10）**：本文旧版提示词的“财务/四流/审批/正式成果”表述只保留作历史参考。任何新 UI 设计必须先遵守《CostLedger_产品基线_施工单位成本岗_v2026-10-10.md》与《开发计划_现行任务清单_v2026-10-10.md》。
> 当前产品是施工单位成本人员的项目经济驾驶舱，不是财务系统、OA、采购/工程/资料系统或正式造价成果制作软件。

## 现行 UI 信息架构

### 产品定位

面向施工单位成本人员，掌握建设单位方向的项目收入、材料供应/劳务分包/专业分包/专业服务方向的项目支出、外部提供的已收/已付资金状态、目标成本、预计最终成本和成本风险。系统只记录外部金额事实、状态、来源、截至日期、管理精度、成本预测和结果摘要。

### 业务板块

- 对上收入：合同收入、变化、报送/确认结果、已收信息；
- 材料供应：材料包金额、已知支出、预计金额、已付信息；
- 劳务分包：劳务成本、过程结果、结算结果、付款状态；
- 专业分包：专业包成本、差异、预计最终成本；
- 专业服务：设计、检测、咨询、运输等服务支出；
- 项目间接费用：管理、临设、措施等项目费用；
- 资金状态：外部提供的已收、已付、待收、待付和资金缺口；
- 成本预测与风险：目标、预测、超支/节余、过期、暂估和未分配。

### 首屏与下钻

首页显示：预计收入、目标成本、预计最终成本、预计利润/利润率、已知支出、外部已收/已付、资金缺口、预计超支、最大风险项、数据截至日期、覆盖率和预测可信度。

下钻顺序为：`项目 → 业务板块 → 成本控制项 → 合同/采购/分包包 → 记录摘要`。过程管理以项目自定义成本控制项为核心，不强制清单逐条录入；只在结算分析且数据具备时进入合同清单级。

### UI 禁止暗示

- 不出现“财务凭证”“财务实际成本”“应付余额”“已确认收入”等越权语义；
- 已收/已付必须显示来源、提供方、截至日期和状态，不能暗示成本人员已核验财务合理性；
- 不设计进度款报量、签证单、收方单、送审结算书的制作界面；
- 不设计图纸、变更文件、报价来源、计价依据、计算底稿或资料归档界面；
- 不要求目标成本、合同清单、采购材料、分包包和结算清单逐项对齐；
- 不把同一往来单位的全局角色当成所有项目和业务板块的角色。

请为我设计一款 **Windows 桌面端「建筑工程成本台账管理系统」** 的高保真 UI 设计稿（Figma/原型风格，非代码）。要求如下：

## 1. 产品定位

面向工程公司的造价与项目管理人员，用于管理「合同、计量签证、成本归集、资金付款、对账」五类业务（即合同流、业务流、资金流、票据流「四流合一」经济成本管控）。不涉工程进度/质量/安全管理。

## 2. 平台与形态

- 形态：**Windows 桌面应用窗口**（非 Web 网页、非手机）。
- 窗口结构：**左侧固定导航栏 + 顶部工具条 + 右侧内容工作区** 经典三栏桌面布局。
- 支持浅色主题（主）与暗色主题（切换）。

## 3. 视觉风格

- 设计语言：**Microsoft Fluent Design**（干净、克制、专业、留白充足），圆角 8–10px，轻投影，矢量图标。
- 气质：企业级财务/工程后台，稳重可信，不花哨；信息密度偏高但分区清晰。
- 字体：中文「微软雅黑 / Segoe UI」，数字用等宽对齐（tabular-nums）。

## 4. 配色（严格遵循）

- 主背景 `#F3F4F6`，卡片/面板 `#FFFFFF`，分隔线 `#E5E7EB`。
- 主色（Accent）`#2F6FED`（蓝），深一档 `#1659D6`。
- 状态色遵循**国内造价习惯**：成本超支/支出用**红色 `#DC2626`** 提示；结余/节省/正常用**绿色 `#16A34A`**；预警用**橙色 `#D97706`**；辅助用紫色 `#7C3AED`、青色 `#0D9488`。
- 文字：主 `#1F2329`，次 `#6B7280`，弱 `#9CA3AF`。

## 5. 布局组件规范

- 左侧导航：Logo「诺」+ 产品名「诺亨成本台账」；分组菜单：经营看板 / 业务单据（合同台账、计量与签证、成本脊柱、资金与付款、对账中心）/ 输出（报表中心、系统设置）。图标用线性 SVG 风格。
- 顶部工具条：当前项目切换器（示例「残疾人项目 · 1248万」）、全局搜索框、主题切换按钮、用户头像。
- 内容区：页面标题 + 副描述；KPI 卡片组；数据表格（带状态标签 Pill、进度条、金额右对齐）；图表区；列表/树形区；操作按钮（主按钮蓝底白字「＋ 新增」）。

## 6. 需生成的画板（每个一屏，共 8 屏）

1. **成本驾驶舱**：4 个 KPI 卡（目标总成本/累计已发生/成本偏差/资金收付款）+ 成本累计曲线折线图（实际红虚线 vs 目标蓝虚线）+ 成本构成环形图（设备材料57%/分包26%/其他17%）+ 待办预警列表。
2. **合同台账**：统一合同表格（编号/名称对方单位/类型标签/合同金额/已计量/已付款/付款进度条/状态），顶部「全部/总包/分包/采购」分段筛选 + 「＋ 新增合同」按钮（点击弹出新增表单弹窗：编号、对方单位、类型下拉、金额）。
3. **计量与签证**：左侧单据列表（进度计量/签证，含状态标签「待确认/已回写」），右侧选中签证明细表（项目/量/单价/合价，合计红色）。
4. **成本脊柱**：树形成本科目表（设备购置费/安装工程费/建筑工程费/其他，逐级展开到明细行），每行显示金额 + 目标对比标签（超支红 / 结余绿）。
5. **资金与付款**：3 个 KPI（累计收款/累计付款/净占用）+ 付款流水表（含「质保金抵扣」「预付款扣回」列）。
6. **对账中心**：三方勾稽差异表（合同计量 vs 实收，差异标红）+ 已对账状态标签区。
7. **报表中心**：仅作目录入口卡片（项目成本月报/资金收支表/分包结算单/增值税进项台账，各带「预览」按钮，注明由报表引擎渲染）。
8. **系统设置**：角色权限列表（造价员/项目经理/财务，标签编辑/审批/对账）+ 数据安全卡（存储 SQLite 预留 SQL Server、审计开关、每日备份）。

## 7. 数据与文案

- 全部用**中文真实工程样例数据**（金额单位「万元」，示例：合同价 1248万、电缆采购 186.3万、签证 18.6万等，可自由合理填充）。
- 注重可点交互示意：导航高亮当前页、按钮 hover、弹窗遮罩、「新增合同」表单。

## 8. 禁忌与要求

- 不画复杂打印报表/套打模板（那部分由 FastReport 类报表引擎负责，本稿只做录入与看板界面）。
- 不使用手机布局；保持桌面专业观感。
- 输出建议：8 个画板同文件，附一套浅色 + 一套暗色变体更佳。

请为我设计一款 **Windows 桌面端「建筑工程成本台账管理系统」** 的高保真 UI 设计稿（Figma/原型风格，非代码），视觉风格模仿 Ramp / Brex 等现代支出管理 SaaS 产品。要求如下：

## 1. 产品定位
面向电力/变配电工程公司的造价与项目管理人员，管理「合同、计量签证、成本归集、资金付款、对账」五类业务（四流合一经济成本管控）。不涉及工程进度/质量/安全。

## 2. 平台与形态
- Windows 桌面应用窗口（非网页、非手机）。
- 布局：**极窄图标式左侧栏（仅线性图标，悬停显名称）** + 顶部面包屑（如「成本看板 / 总览」）+ 问候语标题区（如「下午好，李工」）+ 右侧内容区。
- 看板页布局（重点对齐截图）：问候语 → 4 张粉彩状态卡一行 → 两栏堆叠网格（支出柱状图 / 待我审批；按供方支出 / 费用构成）。**不使用悬浮叠层卡片，保持规整网格。**

## 3. 视觉风格（严格遵循参考截图气质）
- 整体：**极简、轻盈、留白多、几乎无边框**；卡片大圆角 12–16px，极浅柔投影（低不透明度、大扩散），白卡片浮在淡色画布上。
- 画布底色：**暖白/微绿调 `#F6F8F7`**；卡片纯白 `#FFFFFF`。
- 主色：**翡翠绿**（品牌色 `#0E9F6E`，深绿 `#046C4E` 用于按钮与强调文字）。
- 状态块用**粉彩底色大卡**：待批=薄荷绿底 `#D9F2E5`、被驳回=浅粉红底 `#FBE0E0`、进行中=浅琥珀底 `#FCF0D4`，卡内配大号数字与小图标。
- 强调数字：**特大号粗体**（如 ¥1,318.62 风格），标签用小号灰色字。
- 图表：环形图（分段绿色系 + 灰）、横向进度条列表、分组柱状图，均为**圆角端点、无网格线或极浅网格**。
- 图标：1.5px 细线风格，单色深灰。
- 字体：中文「微软雅黑」，数字 Segoe UI 粗体等宽对齐。

## 4. 状态配色约定（国内造价习惯）
- **超支/驳回/异常 = 红色 `#E0574F`**（粉彩底 `#FBE0E0`）。
- **结余/已批准/正常 = 绿色系**（主品牌绿）。
- **待处理 = 琥珀 `#E5A13A`**（粉彩底 `#FCF0D4`）。

## 5. 需生成的画板（8 屏）
1. **成本看板（总览，布局严格照截图）**：顶部问候语标题（如「下午好，李工」）→ 一行 4 张粉彩状态大卡（待批签证 3 / 被驳回 1 / 已结 12 / 草稿 0）→ 下方两栏堆叠布局：第一行左卡「支出 Spend」柱状图（带 月/季 切换），右卡「待我审批」列表（每项含 批准/驳回 圆角按钮）；第二行左卡「按供方支出 Spend by merchant」横向条形列表，右卡「费用构成」环形图（设备材料 57% / 分包 26% / 人工 17%）。不要悬浮叠层，用规整两栏网格。
2. **合同台账**：白卡大圆角表格（编号/对方单位/类型/金额/已付/进度条/状态粉彩标签），顶部搜索 + 筛选胶囊按钮 + 绿色主按钮「＋ 新增合同」。
3. **计量与签证**：左列表右明细两栏卡；状态标签「待甲方签认（琥珀）/已回写（绿）」；明细合计红色。
4. **成本脊柱**：树形成本科目卡（逐级展开），每行「金额 + 预算进度条 + 剩余/超出」——超出用红色文字如「2,450 over」风格。
5. **资金与付款**：3 个大数字 KPI 卡 + 付款流水表（含质保金抵扣列）。
6. **对账中心**：差异卡（红色文字 + 处理按钮）+ 已对账绿色胶囊标签组。
7. **报表中心**：目录卡片 + 每张卡「预览」白底描边按钮（如截图中 Reject/Approve 的克制按钮风）。
8. **系统设置**：角色权限卡 + 数据安全卡。

## 6. 数据与交互
- 中文真实工程样例数据（万元），如合同价 1248万、电缆采购 186.3万、签证 18.6万。
- 示意可交互：导航高亮、按钮 hover、悬浮卡片层次、筛选胶囊选中态。

## 7. 禁忌
- 不画打印/套打报表模板；不做手机布局；不用重边框和深色企业风（保持轻盈）。
- 输出建议：8 画板同文件，附浅色单主题即可（此风格本身即浅色）。

# 版本 B 修订（按用户截图定稿，覆盖版本 B 中的差异描述）

以 Ramp 首页截图为唯一布局与配色基准，精确还原：

## 布局（自上而下）
1. 画布为淡灰绿底色，中央一张白色大圆角应用窗口（圆角约 22px，柔和大投影）。

   - **右栏**：「支出」白卡（支出总额大数字 + 两根大圆角柱状图，一季度浅绿/二季度中绿）→ 下方「费用构成」白卡（右上「本季至今」下拉胶囊；环形图绿色系分段 + 图例）。
6. **两个悬浮面板压在窗口之上**（带明显投影，可部分超出窗口边缘）：
   - 右上「审批」面板：小字单据编号 + 大字「审批」+ 右侧合计金额；三行审批人（彩色首字圆角块/截止日期/状态——绿色对勾「已同意」、琥珀「待审」）；底部「驳回」（白底红字红描边）+「同意」（深绿实心）按钮。

## 配色（精确值）

## 硬性要求
- **全页面禁用 emoji**，所有图标一律 1.5px 细线 SVG（线性、单色）。
- 中文界面，微软雅黑；数字大号粗体、右对齐；金额千分位。
- 数据用真实工程样例：合同 ¥12,486,000、支出总额 ¥9,361,000、签证 ¥186,000、供方 远东/北源/昆明/起帆。
