# CostLedger 现行开发计划与任务清单（v2026-10-10）

> 本清单服务于《CostLedger_产品基线_施工单位成本岗_v2026-10-10.md》。它覆盖旧 M1–M5 计划，优先解决产品边界和模型方向，不以旧代码已经存在的实体作为正确前提。

## 1. 本轮冻结的边界

- 用户角色：施工单位成本人员。
- 上游关系：建设单位/甲方，关注项目收入、变化、报送/确认结果和已收信息。
- 下游关系：材料供应、劳务分包、专业分包、专业服务，关注支出、预计成本、结算压力和已付信息。
- 核心结果：收入、支出、资金状态、目标成本、预计最终成本、预计利润、超支和成本风险。
- 外部金额：只记录来源、提供方、截至日期、数据状态和管理精度；不作为财务确认。
- 过程粒度：以成本控制项为核心，不强制目标成本、合同清单、采购材料和结算清单逐项对齐。
- 结算粒度：需要时才进入合同清单级；清单级不是过程录入前提。
- 明确不做：财务核算、采购执行、工程施工管理、资料归档、OA 审批、进度款报量、签证单、收方单、送审结算书、计价依据、图纸/变更文件/报价来源/计算底稿。

## 2. 任务状态规则

`待办` 表示尚未开发；`验证中` 表示有代码但未按新基线验收；`保留` 表示可复用但需重新定位；`冻结` 表示不再扩展；`完成` 必须有测试或真实样例证据。

## 4. 首个垂直切片

用一个真实项目的脱敏汇总数据，不要求清单逐项录入，跑通：

```text
建设单位收入合同
  + 材料供应包 / 劳务分包包 / 专业分包包 / 专业服务包
  + 项目间接费用
  + 外部已收、已付信息
  → 10～30 个成本控制项分配
  → 目标成本 + 当前预计最终成本
  → 项目利润/超支/资金风险/数据精度驾驶舱
```

验收必须包含一个无法逐项对齐的场景：目标成本按专业、采购按材料包、分包按合同包、结算按清单；系统仍能正确保留来源粒度、汇总到控制项，并显示暂估或未分配金额。

## 5. 开发闸门

1. P0 通过前不新增财务、采购、工程、资料或 OA 功能。
2. P1 通过前不把 `CostEntry`、`Payment` 或 `ContractLine` 作为所有成本结果的唯一来源。
3. P2 通过前不要求用户为过程记录补录清单项。
4. P3 通过前不宣称 EAC/超支为财务结论；所有预测必须显示来源、日期、精度和假设。
5. P4 通过前不接入专业打印报表引擎或生成正式造价成果。
