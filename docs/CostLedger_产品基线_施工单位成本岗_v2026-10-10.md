# CostLedger 产品基线：施工单位成本岗（v2026-10-10）

> 本文是当前产品定位、业务边界和后续开发的最高优先级基线。它修正旧文档中“财务凭证中心、清单逐项强对齐、正式成果制作、四流/审批系统”等超出岗位范围的假设。旧文档保留为历史记录，但与本文冲突时以本文为准。

## 1. 产品定位

CostLedger 是**施工单位成本人员使用的工程项目经济状态与成本风险管理系统**。

它帮助成本人员掌握：

- 对上项目收入：合同收入、已知变化、预计最终收入、已报/已确认结果、外部提供的已收信息；
- 对下项目支出：材料供应、劳务分包、专业分包、专业服务、项目间接费用等已知金额与预计金额；
- 项目资金状态：已收、已付、待收、待付、资金缺口和数据截至日期；
- 项目成本状态：目标成本、当前预计最终成本、预计利润、超支/节余及风险来源；
- 成本数据的管理精度：项目级、专业级、合同包级、成本控制项级、清单级。

它不是：

- 财务系统，不做总账、会计核算、付款审批、发票认证或资金正确性判断；
- OA 系统，不做跨部门审批、催办、权限流程或对上下游单位的业务管控；
- 工程/采购/仓储系统，不做施工进度、采购执行、收发存、质量安全或供应商履约管理；
- 资料系统，不保存图纸、变更文件、报价来源、计价依据、计算底稿或正式档案；
- 造价成果制作软件，不制作进度款报量、签证单、收方单、送审结算书等岗位输出成果；
- 专业计价软件，不替代清单计价、定额计价、算量或结算编制软件。

系统记录的是成本人员用于项目管理的**金额事实、状态、预测和管理判断**，不是把外部部门的责任转移给成本人员。

## 2. 施工单位成本人员的角色定位

成本人员处于项目经济信息的中间位置：向上关注建设单位方向的收入与回款，向下关注材料、劳务、专业分包和专业服务形成的项目支出与结算压力；同时向项目管理层解释目标成本、预计最终成本、利润和风险。

同一个往来单位在不同业务板块中的角色可能不同，不能只用一个全局 `PartyRole` 推断所有口径。角色必须挂在**项目/合同/业务关系**上。

| 关系方向 | 对方单位 | 成本人员关心什么 | 系统记录什么 | 明确不做什么 |
|---|---|---|---|---|
| 对上 | 建设单位/甲方 | 合同收入、变更影响、计量/结算结果、已收与未收、收入风险 | 对上合同、变化事项、成果结果、收款外部信息 | 不做甲方审批，不制作报量/签证/结算书，不确认财务收入 |
| 对下 | 材料供应单位 | 材料合同/采购包金额、已知支出、结算压力、付款状态 | 材料供应关系、金额汇总、外部付款信息、成本控制项分配 | 不做采购执行、询比价、到货验收、仓储和供应商管理 |
| 对下 | 劳务分包单位 | 分包合同、预计分包成本、完成情况、结算/付款压力 | 劳务分包关系、过程结果、结算结果、外部付款信息 | 不做劳务现场管理、工资代发和分包审批 |
| 对下 | 专业分包单位 | 专业包收入/成本、完成情况、结算差异、预计最终成本 | 专业分包关系、成本控制项分配、结算结果、资金状态 | 不做专业施工管理和分包履约管理 |
| 对下/横向 | 专业服务单位 | 设计、检测、咨询、运输等服务支出及预计成本 | 专业服务关系、金额事实、预测和风险 | 不做服务采购、成果质量和合同执行管理 |
| 项目内部 | 项目部/经营/工程等 | 获取截至某日的金额、完成和变化信息，形成成本判断 | 来源、提供方、截至日期、数据状态、精度和备注 | 不把对方提供的数据包装成成本人员已核实的事实 |

同一单位可同时是建设单位、供应单位或专业服务单位，但每个关系必须明确：

```text
项目 + 我方角色 + 对方单位 + 合同/业务关系 + 方向 + 业务板块
```

## 3. 业务板块

业务板块不是简单的菜单分类，而是决定字段、金额方向、状态和分析口径的边界。

| 板块 | 核心问题 | 主要金额 | 典型精度 |
|---|---|---|---|
| 对上收入 | 项目能取得多少收入，当前预计收入是多少 | 合同收入、变化、报送/确认结果、已收信息 | 项目/合同包 |
| 材料供应 | 材料相关支出和未来成本压力是多少 | 采购/供应包金额、已知支出、预计金额、已付信息 | 专业/材料包 |
| 劳务分包 | 劳务成本预计多少，结算和资金压力如何 | 分包合同、预计成本、结算结果、已付信息 | 专业/分包包 |
| 专业分包 | 专业工程包的收入/成本和风险如何 | 合同包、过程结果、结算结果、预测 | 专业/合同包 |
| 专业服务 | 设计、检测、咨询等支出是否进入预测 | 合同/已知金额/预计金额 | 项目/服务包 |
| 项目间接费用 | 管理、临设、措施等不易挂清单的费用 | 目标、已知支出、预计最终 | 项目/费用包 |
| 项目资金状态 | 项目资金是否有压力 | 外部提供的已收、已付、待收、待付 | 项目/合同 |
| 成本预测与风险 | 是否超支，风险从哪里来 | 目标、当前预测、差额、风险事项 | 成本控制项 |
| 结算结果 | 外部成果对最终收入/支出的影响 | 报送、核对、审定、累计结果 | 合同/成果；必要时清单 |

系统可以登记一个对象，但必须在板块中解释其含义。例如：对上合同金额是收入基准，对下合同金额是支出或成本预测输入；同一个 `Amount` 不能跨板块直接相加。

### 3.1 板块、角色与金额方向的硬约束

这三者不是自由组合。以下矩阵由领域层 `BusinessSegmentRules` 强制，任何录入入口、后台配置或动态字段都不得绕过：

| 业务板块 | 允许的对方角色 | 允许的金额方向 |
|---|---|---|
| 对上收入 | 建设单位 | 收入、中性 |
| 材料供应 | 材料供应单位 | 支出、中性 |
| 劳务分包 | 劳务分包单位 | 支出、中性 |
| 专业分包 | 专业分包单位 | 支出、中性 |
| 专业服务 | 专业服务单位 | 支出、中性 |
| 项目间接费用 | 项目部/内部提供 | 支出、中性 |
| 项目资金状态 | 上述任一外部单位 | **仅**已收、已付 |
| 成本预测与风险 | 任一 | 中性 |
| 结算结果 | 任一 | 收入、支出、中性 |

配套规则：

- 登记带往来单位的金额事实前，必须先在该项目、该板块建立业务关系；金额方向沿用关系上确定的方向，避免同一单位在不同板块被写成同一口径。
- 关系挂合同（可选）时，合同必须与关系属于同一项目，防止跨项目串用收入/支出口径。
- 对上收入与项目资金状态**不计入**"待归属金额"的分母：合同收入和已收/已付不是同一件事，不需要也不应该被分配到成本控制项。

### 3.2 角色可增补，板块与方向不可增补（方案 A，2026-10-10 用户拍板）

实际项目的往来单位类型远多于预设六种（机械租赁、检测、运输、劳务班组、爆破……）。因此：

- **角色**：由字典「项目业务角色」（`ProjectPartyRole`）定义，后台字典管理可增删停用；新增角色经「板块角色授权」（`SegmentRolePermission`）增补到指定板块后即可用于登记业务关系。内置六角色（建设单位 / 材料供应 / 劳务分包 / 专业分包 / 专业服务 / 项目部内部）随账套种子提供。
- **不可增补**：业务板块本身、金额方向、管理精度、数据状态。它们决定成本口径，必须是强类型，配置与动态字段一律不得新增或放宽。授权只解决"这个角色能不能进这个板块"，不解决"这个板块能不能出现收入方向"。
- 撤权只影响后续登记，已建立的业务关系不被抹掉；停用的字典角色不能再登记新关系（与字典可见性规则一致）。

## 3.3 内部汇报报表的口径声明（不是对外成果）

系统不制作对外成果文件（报量、签证、收方、送审结算书），但**必须支持成本岗向领导汇报的内部报表打印**：A4 版式、可另存 PDF。这类报表属于对内管理信息，与对外商务文件的关键区别是必须自带口径声明：

```text
数据截至：YYYY-MM-DD　编制：成本岗
未付（推算）＝对下合同额 − 已登记付款
未收（推算）＝对上合同额 − 已登记收款
以上为推算差额，不等于财务应付/应收账款（未含未开票、质保金、暂扣等因素），
成本岗不对其完整性与合规性作出判断。
```

"未付/未收"必须带"（推算）"：合同额与已登记金额是成本岗手上的依据，差额是算出来的，不等于财务应付账款；不加限定，成本岗就在替别人的数据背书。
## 4. 多粒度原则：过程粗、结算细

真实项目中，目标成本、合同清单、采购材料、专业分包和结算清单通常不能逐项对齐。系统禁止把以下关系作为前提：

```text
目标成本清单项 = 合同清单项 = 采购材料项 = 结算清单项
```

过程管理采用**成本控制项**作为中间管理层。成本控制项是成本人员为了看目标、预测、差异和风险建立的稳定口径，不等同于合同清单、财务科目或施工 WBS。

支持不同来源以不同精度进入同一成本控制项：

```text
项目 → 成本控制项 → 合同包/采购包/分包包
结算阶段按需要 → 合同清单项
```

允许：一对一、一对多、多对一、暂估分配和未分配。每条分配记录至少包含：来源记录、成本控制项、金额/比例、分配精度、分配状态、截至日期和备注。

精度枚举：`项目级`、`专业级`、`合同包级`、`成本控制项级`、`清单级`。

任何汇总必须保留精度，不得把专业级金额伪装成清单级精确结果。系统应展示：

- 当前金额覆盖率；
- 各来源的管理精度；
- 未分配金额；
- 暂估金额；
- 数据截至日期；
- 预测可信度。

清单级只在数据天然具备或结算阶段确有必要时使用，不作为过程录入的强制字段。

## 5. 金额口径

### 5.1 成本人员负责的判断

- 目标成本：成本人员采用的管理基准及其版本；
- 已知支出：从项目、经营、采购或其他部门获得的金额信息；
- 当前预计最终成本：成本人员基于当前信息的管理预测；
- 预计利润/超支：收入预测与成本预测的差额；
- 风险金额：尚未确定但可能影响项目经济结果的估计。

### 5.2 外部提供的事实

付款、收款、合同金额、采购金额、分包结算金额等可以进入系统，但每条都带：金额、方向、日期、截至日期、来源、提供方、数据状态和备注。

数据状态建议为：`估计`、`外部提供`、`已核对`、`已过期`、`待确认`。`已核对`只表示成本人员完成了约定范围内的核对，不代表财务确认或会计确认。

### 5.3 不使用的语义

系统不把“成本凭证”“财务实际成本”“应付余额”“已确认收入”作为成本人员必须提供的前提。若历史代码保留 `CostEntry`，应重新定位为来源可追溯的外部金额/成本管理记录，不能代替财务账。

### 5.4 预测的四个数与冻结语义

“当前预计最终成本”是成本人员的管理预测，不是算出来的唯一真相。每个预测版本按成本控制项展开四个数：

```text
目标成本       成本人员采用的基准
已知金额       由外部金额事实按分配关系归集（不接受手填，保证有依据）
剩余估计       成本人员对未完部分的估计
风险调整       可正可负（涨价、工程量偏差为正；可争取的节约为负）
预计最终 = 已知金额 + 剩余估计 + 风险调整（派生值，不是第四个录入项）
```

规则：

- 修订产生新版本，**冻结后的版本不可改写**；历史报表因此能解释“当时依据什么算”，不会因后来补录数据而漂移。
- 冻结必须写明**编制假设**（价格水平、剩余工程量依据、未确认事项如何处理）；没有假设就不允许对外给出预计最终成本。
- 存在未归属金额时，可信度上限被系统压低（高→中，其余→低）。数据不足就显示“低置信度”，不输出看似精确的数字。
- 每行的可信颗粒度以该控制项**最粗来源精度**封顶，粗颗粒过程数据不能被包装成清单级结论。
- 没有冻结版本时，界面显示“尚无预测版本”，**不得用已知支出或已付金额冒充预计最终成本**。

### 5.5 变化事项的四个金额必须分开

同一变化事项（设计变更、现场签证、范围调整、价格变化等）分别保存：

```text
成本人员测算金额   我方造价判断
对方报送金额       外部提供，未核实
外部确认金额       对方书面认可数额（不是财务入账结论）
纳入当前预测金额   由成本人员决定
```

四者相互独立、互不覆盖：对方报送 135 万不能把我的测算 120 万改掉，我也不能把自己的测算写成对方已认可。

“已测算但暂未纳入预测”是**允许状态**，系统必须在汇总中显示这部分金额（未纳入预测的变化金额），而不是拒绝录入或静默漏掉；明确不纳入时用“不纳入当前预测”状态，避免用 0 表达歧义。

## 6. 不制作成果，但记录成果结果

系统不编制进度款报量、签证单、收方单、送审结算书，不保存图纸、变更文件、报价来源、计价依据和计算底稿。成本人员可在成果完成后记录其**结果摘要**：成果类型、期次、报送金额、外部核对/确认金额、差额、影响的成本控制项、状态、来源、截至日期。

成果状态只描述管理信息：`未录入`、`已测算`、`已报送`、`外部反馈`、`已确认`、`不纳入当前预测`；不构成 OA 审批。

## 7. 目标产品首页

项目经济驾驶舱应回答：

```text
项目预计收入       当前预计最终成本       预计利润/利润率
已知项目支出       外部提供已收/已付       资金缺口/资金风险
目标成本           预计超支/节余           最大风险项
数据截至日期       金额精度/覆盖率         未分配/暂估金额
```

首页下钻顺序：`项目 → 业务板块 → 成本控制项 → 合同/采购/分包包 → 记录摘要`。只有结算分析才继续到清单项。

## 8. 新路线

1. **P0 产品重定向**：把旧“凭证、四流、清单强制挂接、成果打印、全动态平台”标为历史方案；冻结本基线和角色矩阵。
2. **P1 经济驾驶舱**：重做收入、支出、资金、成本、风险五类摘要，所有外部金额附来源和截至日期。
3. **P1 成本控制项**：建立项目自定义的过程管理口径，支持多粒度、多来源、多对多和暂估分配。
4. **P1 变化与预测**：记录变更/签证/索赔等对预测的影响，不制作原始成果；区分成本人员估计、外部反馈和确认结果。
5. **P2 业务板块**：分别实现对上收入、材料供应、劳务分包、专业分包、专业服务、间接费用和资金状态视图，共享往来单位但不共享业务口径。
6. **P2 结算分析**：允许清单级对齐、报送与审定结果对比，但不扩展为计价软件。
7. **P3 可靠性**：版本快照、数据精度/覆盖率、过期提醒、预测可信度和可解释差异；暂不扩展 OA、资料、采购、财务和动态低代码能力。

## 9. 验收原则

- 不录入财务付款凭证，也能展示项目收入、支出、资金、成本和风险；
- 同一往来单位在不同项目/合同/板块可承担不同角色和金额方向；
- 过程数据不挂清单项也能参与专业级或成本控制项级分析；
- 目标成本、合同、采购、分包和结算无法逐项对齐时，系统能保留原始粒度并显示暂估/未分配；
- 清单级只在需要时启用；
- 系统不生成或保存用户明确排除的正式成果、计价依据、图纸、报价来源和底稿；
- “已收/已付”与“预计收入/预计成本”分开显示，且均有截至日期和数据状态；
- 风险结论能指出板块、控制项、数据精度和主要假设，不能伪装成财务结论。
