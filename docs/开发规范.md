# CostLedger 开发规范（施工单位成本岗基线）

> 适用范围：CostLedger 成本管理系统全部工作——代码仓库 `CostLedger/`、项目规划文档、UI/设计资产。
> 性质：本规范为**可执行约束**，非建议。违反任一条即视为不合格交付。
> 基线：M1 已验证（git 基线 commit `486a368`）。
> **产品基线更新（2026-10-10）**：以《CostLedger_产品基线_施工单位成本岗_v2026-10-10.md》为最高优先级。本文中的“成本”指施工单位成本岗的项目经济管理，不指财务总账；旧文档中的财务凭证中心、清单逐项强对齐和正式成果制作假设均已废止。

---

## 1. 核心铁律：成本管理边界不可越界

系统的数学口径是项目经济管理的根基，**绝不允许**通过后台配置、动态字段或任何用户入口改变其定义；同时不得把成本岗无法核实的外部金额伪装成财务结论：

- **成本人员口径**：目标成本 / 当前预计最终成本 / 预计利润或超支 / 风险金额，必须区分基准、事实和预测。
- **外部金额事实**：收入、支出、已收、已付、合同、采购包、分包和结算金额必须带来源、提供方、截至日期、数据状态和精度。
- **业务板块隔离**：对上收入、材料供应、劳务分包、专业分包、专业服务、间接费用、资金状态和成本预测不能因共用往来单位而混用金额方向。
- **成本控制项优先**：过程管理不强制逐条清单对齐；允许项目级、专业级、合同包级、控制项级和清单级，并保留未分配/暂估状态。
- **来源可追溯**：历史 `CostEntry` 只能作为兼容层的成本管理记录，不得称为财务付款凭证，不得替代财务核算。
- **正式成果边界**：系统不制作进度款报量、签证单、收方单、送审结算书，不保存图纸、变更文件、报价来源、计价依据和计算底稿。

配置系统只管理字典、扩展字段和数据报表/看板展现，**绝不**创建新的成本计算口径，也不能改变业务板块、金额状态和数据精度的语义。架构上以强类型 Domain 实体 + 单元测试形成硬隔离。动态能力近期冻结，不得先于成本控制项和经济驾驶舱扩展。

## 2. 技术栈与架构锁定

- **技术栈**：.NET 9 + Avalonia 11.2（Skia / XAML / MVVM）+ EF Core + SQLite。
- **报表分两层（2026-10-09 用户确认，消除 §2/§9 原措辞歧义）**：
  1. **数据报表 / 查询**（选数据源、列、筛选、聚合；屏幕预览）= 自研能力，服务于项目经济状态、成本预测、差异和风险。
  2. **外部成果结果登记** = 只登记进度款报量、签证、收方、送审结算等成果的金额摘要、状态和影响，不生成成果文件。
  3. **明确禁止**：不引入专业打印引擎来制作正式造价成果；不保存成果所依赖的图纸、变更文件、报价来源、计价依据和底稿。
- **分层（依赖方向单向，禁止反向）**：
  - `CostLedger.Domain`：纯净领域模型，不引用 EF Core、不引用 UI。
  - `CostLedger.Infrastructure`：EF Core、DbContext、Repository 实现；`IRepository` 抽象预留 SQL Server 切换。
  - `CostLedger.App`：Avalonia UI、ViewModel、视图、转换器、样式。
- 不轻易更换技术栈；确需更换须先与用户确认并写入开发计划。

## 5. 编码规范：禁止屎山代码

交付代码必须满足以下"反屎山"底线：

- **单一职责**：方法不超过一屏（≈80 行），类不超过一个清晰职责；禁止"神类 / 神方法"。
- **DRY**：相同逻辑抽取为服务 / 扩展方法，禁止复制粘贴跨文件重复。
- **无魔法值**：税率、口径、状态等业务常量集中定义或来自配置，禁止在业务代码里散落裸数字 / 字符串。
- **分层纯净**：业务计算只在 Domain / Service，禁止在 ViewModel / View / Converter 里写算账逻辑。
- **异常不吞**：禁止空 `catch`、禁止吞掉异常后返回默认值伪装成功。
- **命名可读**：域模型用英文 PascalCase；方法 / 变量名表达意图；对业务口径以中文注释说明"为什么"。
- **可测性**：核心计算以纯函数 / 服务暴露，便于单测，不藏在 UI 事件里。
- **不过度也不偷工**：反对为"将来可能"引入冗余抽象；但也不允许为图快而堆 `if-else` 分支绕过既有模式（M1→M2 已确立的扩展点应复用）。

---

## 6. 复用优先：避免重复造轮子

- 能引用已有模块 / 类直接引用，能接入已有服务 / 依赖直接接入，**禁止重造**。
- 具体约束：
  - 收入、支出、资金、成本预测等计算复用统一的经济状态查询模块，不把付款或收款直接当成成本；兼容代码中的 `CostSpineService` 逐步按新口径重构。
  - 配置化需求走既定元数据驱动方案（`EntityDef` / `FieldDef` / `LookupDef` + 通用渲染器），不临时手写独立表单。
  - 第三方能力（OCR、报表、图表、云服务等）优先选用已评估 / 已接入方案，不重复选型。
  - **禁止引用被用户否定的旧资产**（如 `cost-automation`，用户已认定为不可维护代码），不从其复制逻辑。

## 9. 配置化边界（平台化方向）

- 平台化目标 = **元数据驱动**（注册表 + 通用渲染器），不是 Odoo 式可视化拖拽建表器（工程量 / 风险过高）。
- 主数据 / 字典为全局共享库，但往来单位的角色必须挂在项目/合同/业务关系上，不能仅靠一个全局 PartyRole 推断口径；成本控制项属于项目管理口径，不等同于合同清单。
- 业务板块固定为：对上收入、材料供应、劳务分包、专业分包、专业服务、项目间接费用、项目资金状态、成本预测与风险、结算结果。
- **板块 ↔ 角色 ↔ 金额方向为领域层硬约束**（`Domain/EconomicManagement.cs` 的 `BusinessSegmentRules`）：矩阵见《CostLedger_产品基线_施工单位成本岗_v2026-10-10.md》§3.1。项目资金状态只允许已收/已付；登记挂往来单位的金额前必须已建立该板块的业务关系，方向沿用关系；关系挂合同时合同必须同项目。**任何录入入口、字典配置或动态字段都不得绕过或改写该矩阵。**
- **角色字典化（方案 A，2026-10-10 用户拍板）**：角色代码由字典 `ProjectPartyRole` 定义，**后台可增补**（如机械租赁、检测、运输单位）；`SegmentRolePermission`（"板块角色授权"）把新增角色增补到某板块。**但业务板块、金额方向、精度、状态仍是强类型枚举，配置不得新增板块、不得放宽方向**（`GrantSegmentRoleAsync` 拒绝授权字典外角色；方向校验独立于授权）。停用的字典角色不能再登记新关系；撤权只影响后续登记，不抹掉已建立关系。
- **内部汇报报表必须带口径声明**：`未付（推算）/ 未收（推算）`＝合同额与已登记金额之差，**不等于财务应付/应收账款**。文案单一来源 `Infrastructure/PartyLedgerCaliber.Build`，随数据截至日期一起输出；版式渲染在 `Infrastructure/A4ReportLayout`（纯函数，可单测），App 层 `PrintService` 只负责打开浏览器。
- **汇总不得提升颗粒度**：`CostControlItemSummary.CoarsestSourcePrecision` 取来源中最粗的精度作为该控制项可信颗粒度封顶；粗颗粒过程数据与细颗粒结算数据可并存，但结论不得伪装成清单级。
- **预测已知金额只能由分配推导**：`CostForecastLine.KnownAmount` 由 `ManagementAllocation` 计算，**不接受手填**；预计最终 = 已知 + 剩余估计 + 风险调整，是派生值。冻结版本不可改写、不可重复冻结，修订必须新建版本；缺编制假设或无预测行拒绝冻结；存在未归属金额时可信度被自动压低。没有冻结版本时不得对外显示“预计最终成本”。
- **变化事项四金额互不覆盖**：成本人员测算 / 对方报送 / 外部确认 / 纳入当前预测各自独立保存（`ChangeItem`）。禁止用对方报送覆盖我方测算，禁止把我方测算当作对方已认可。`ForecastRules` 只约束“尚未测算不得填纳入金额”和“明确不纳入不得填非零纳入金额”；**“已测算但暂未纳入预测”是合法状态**，由汇总提示金额，不得拒绝录入。
- **待分配分母排除对上收入与资金状态**：合同收入与已收/已付不是同一件事，不应被分配到成本控制项；见 `AllocatableSegments`。
- 过程数据允许多对多分配和暂估；清单级只在结算分析或数据天然具备时使用。
- 扩展字段（`FieldDef`）只挂在核心实体"边框"，不参与成本归集计算。
- 报表 / 看板自定义：**数据报表**（自研）= 预置 + 参数 / 列·筛选·聚合配置，见 §2；**打印报表版式**归 M5 专业引擎，不在自研层堆版式。看板 = 显隐排序 + 可视化拼装 KPI。KPI 公式优先可视化拼装，复杂场景再开文本表达式。

- **凭据不硬编码**：GitHub PAT 等已迁移至 Windows Credential Manager；配置（SMM 账号等）走 `.env` / 凭据管理器，不进代码与文档明文。

- `.workbuddy/` 记忆目录禁止删除或改动其自动管理机制。
