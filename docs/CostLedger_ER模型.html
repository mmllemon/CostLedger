现行新增/重定位对象职责关键规则
ProjectPartyRelationship 已实现 v10项目内往来关系项目 + 对方单位 + 我方角色 + 合同(可选) + 业务板块 + 金额方向；同一 Party 可在同一项目承担多种关系。板块决定允许的角色与方向（BusinessSegmentRules，领域层强制），合同跨项目被拒绝。
BusinessSegment 已实现 v10业务板块对上收入、材料供应、劳务分包、专业分包、专业服务、间接费用、资金状态、成本预测/风险、结算结果。资金状态板块只允许已收/已付方向，且不计入"待分配"分母。
CostControlItem 已实现 v10过程成本控制项项目自定义稳定口径（项目+编码唯一），不等同合同清单、采购材料、成本科目或 WBS；可由多来源粗粒度进入。UI 待接入。
ExternalAmountFact 已实现 v10外部金额事实合同/支出/收款/付款/结算等；必须带来源、截至日期、状态、精度，不构成财务确认。挂对方单位时方向沿用其已建立的业务关系，未建关系拒绝登记。
ManagementAllocation 已实现 v10来源到控制项的分配支持一对多、多对一、暂估、未分配；精度为项目/专业/合同包/控制项/清单级。同项目校验、正金额、累计不超来源金额，写入走事务。
汇总视图 已实现 v10控制项/板块/项目经济摘要SummarizeControlItemsAsync 报告每控制项最粗来源精度作为可信颗粒度封顶；SummarizeProjectAsync 分栏给出预计收入、已知支出、已收、已付、资金压力、待分配、暂估、覆盖率、待确认/过期金额与截至日期。
CostForecastVersion + CostForecastLine 已实现 v11成本预测版本 / 按控制项的预测行版本号项目内唯一递增。已知金额由分配关系自动计算，不接受手填；预计最终 = 已知 + 剩余估计 + 风险调整（派生值，不是第四个录入项）。每行带 PrecisionCap＝该控制项最粗来源精度。冻结后不可改写，修订必须新建版本；无预测行或缺编制假设拒绝冻结；存在未归属金额时可信度被自动压低。
ChangeItem 已实现 v11变化事项的成本影响四个金额相互独立：成本人员测算 / 对方报送 / 外部确认 / 纳入当前预测，互不覆盖。事项编号、截至日期、来源必填；控制项与合同跨项目拒绝。状态（未测算·已测算·已报送·外部反馈·已确认·不纳入）决定哪些金额必须存在；"已测算但暂未纳入预测"是允许状态，由汇总提示金额而非拒绝录入。
预测汇总 已实现 v11CostForecastService.GetSummaryAsync目标 / 已知 / 剩余估计 / 风险调整 / 预计最终 / 差额分栏，另给未归属金额、未纳入预测的变化金额、依赖未确认事项的金额、覆盖率、活跃控制项数、与上一冻结版本的预测变化额。草稿按当前分配重算，冻结版本保持当时快照不被后来数据漂移。
M1 已实现（历史凭证内核，强类型硬编码；现降级为兼容层） M2 已实现（A 元数据/B 编辑器/C 报表/D 看板/E 业务单据） 计划待补充字段（未落地） 待定规则 连线标 1:* 一对多 · *:1 多对一 · ↔ 勾稽

核心关联逻辑（真实四流 = 合同 / 发票 / 货 / 资金）：
① 合同流：Project 1—* Contract，Contract 1—* ContractLine（合同行映射成本科目，是「目标成本」基数）。
② 发票流：Contract/Party 1—* Invoice（进项/销项、专用/普通、价税分离），与 Payment 勾稽；不写成本脊柱。
③ 货流：Contract 1—* MaterialReceipt（甲供/乙供），乙供确认后回写 CostEntry（已发生），甲供仅登记。
④ 资金流：Party 1—* Payment（含质保扣/预付扣），与 Invoice 勾稽。
⑤ 业务确认（计量/签证）：Measurement 1—* MeasurementLine，签认后回写 CostEntry。
⑥ 变更令：ChangeOrder 1—* （按 CostCategory 映射）→ 计入 CostSpineLine.Target（目标口径），不写 CostEntry。
⑦ 成本脊柱（唯一数据源，非四流之一）：所有"已发生"只经 CostWriteBackService 追加 CostEntry（不可改、幂等），按 (Project, CostCategory) 聚合为 CostSpineLine；Settlement 用于锁定「预计最终」。
⑧ 平台层：元数据层（EntityDef/FieldDef/LookupDef/LookupItem/CustomFieldValue）驱动通用记录编辑器；报表层（ReportDef/Column/Filter）与看板层（DashboardWidget）仅做展现，不参与算账。
⑨ 预警与调度层（M3-A）：AlertRule 定义规则（复用 DashboardService 指标），AlertRecord 留痕（同规则+项目未确认去重），ScheduledTask 按间隔由后台调度器评估；纯规则驱动、无 AI，只读业务数据、不参与算账。
⑩ 对账引擎（M3-B/C）：不新增实体，读成本脊柱与单据做聚合——合同 vs 成本、三算对比（目标/实际/结算）、按科目 目标 vs 实际、对上 vs 对下（Main=对上合同额，其余=对下；差额=毛利空间）、资金 vs 应付应收（应付=已发生成本/已付，应收=对上合同额/已收）、收款/付款台账（合同额/累计/比例/未收(付)）；只读、不写回。另含 MoneyUtil 人民币中文大写。
系统定位（2026-10-09 用户明确）：本系统 = 项目成本与资金台账 + 分析/预警；非 OA（不做审批流）、不做对下游单位管控、不生成对甲方的报量/签证/进度款资料（甲方各异无法统一）。对手方只是"算账对象"。据此已收敛：删除付款试算/质保抵扣/预付款抵扣，收付款改为"记录+累计"台账。
